# Community profile

One short document that tells every skill how this community works, so the manager is
never asked the same thing twice. The getting-started skill writes it; every other skill
reads it before doing anything else.

It describes the community, not its members: no member names, no contact details, no
notes about individuals. The manager's own name for the sign-off is fine.

This reference file is the template and the rules. It is not any community's profile:
never read it as one.

## Where to find it

Look in this order and stop at the first one you find:

1. Earlier in this conversation.
2. The project's instructions, or a file whose name or title says "Community profile"
   (`community-profile.md`, `community_profile.md`, a document titled "Community
   profile: [name]").
3. A Notion page or Google Doc titled "Community profile", if Notion or Google Drive is
   connected. One search by title; don't browse.
4. A file the manager uploaded.

If two versions disagree, use the one with the later `Updated` date and mention the
other. If there is none, don't stop and don't send the manager off to set one up: use the
defaults below, say in one line which ones you used, and carry on. Offer once, in Next
steps, to save them ("say: set up my community profile").

## How to use it

- Read any layout. The manager's own profile may not follow the template below; map its
  lines to the template's fields by meaning.
- Never re-ask what it already says. Ask only about what it leaves out, and only if it
  blocks the next step.
- What the manager says in this conversation beats the profile. Follow it, then offer to
  update the profile.
- Use its word for members and its language in every member-facing draft, and format
  drafts for its channel (`message-craft.md`, Channels).
- Its "Who can be messaged" line is the opt-in rule for guardrails §10. If it says
  nothing, ask before drafting outreach.
- Read sources where it says they live before looking anywhere else.

## Template

Fill what you know, write `unknown` for the rest, and keep it under about 300 words.

```text
Community profile
Updated: YYYY-MM-DD

Community: [name], a [professional network / association / alumni group / members' club / cohort / event series], about [size] [members word]
Members are called: [members / fellows / alumni / founders / guests]
Language: [e.g. English (UK spelling)]
Time zone: [e.g. Europe/London]

Member records: [e.g. HubSpot, lifecycle stage = Member / Airtable base "Members" / Google Sheet "Members 2026"]
Events: [e.g. Luma calendar "[name]" / Eventbrite (exports) / none]
Where members talk: [e.g. Slack workspace / Discord server / WhatsApp group (exports) / none]
Other sources: [e.g. application form in Tally, newsletter in Mailchimp, meeting notes in Fireflies]

Channels for member messages: [main channel; others and when, e.g. "WhatsApp; email for intros to investors"]
Who can be messaged: [e.g. current members about anything; event guests about that event only; never anyone marked opted out]
Voice: [e.g. warm, direct, first names, no emojis]
Sign-off: [e.g. "Jason"]

Intro ledger: [e.g. Notion database "Intro ledger" / Google Sheet "Intro ledger" / CSV I upload / not started]
Member directory: [e.g. Google Sheet "Member directory" / Airtable table / CSV I upload / not built yet]
Regular sends: [e.g. newsletter every other Thursday; used for spacing checks]
```

## Defaults when a line is missing

| Line | Default |
|---|---|
| Members are called | "members" |
| Language | the language and spelling the manager writes in |
| Time zone | the event's time zone for event timing; otherwise the manager's, stated |
| Channels | plain chat text that works in WhatsApp, SMS or a DM; say so |
| Who can be messaged | none: ask before drafting outreach (guardrails §10) |
| Voice | warm, plain, first person, first names, no emojis |
| Sign-off | the manager's first name if known, else `[your name]` |
| Intro ledger, member directory | look for existing ones first; else the preference order in `ledger.md` |
| Regular sends | ask what went out in the last 7 days before drafting a batch |

## Updating it

- When the manager says something that changes a line (a new channel, the ledger moved,
  a new opt-in rule), name the line and offer the update in one sentence.
- Update a connected Notion page or Google Doc only after a yes, and only the lines that
  changed. Otherwise give the updated text to paste. Change `Updated` either way.
- Never add member data to it. A removal or opt-out request belongs in the ledger and the
  member directory (`guardrails.md` §12), not here.
